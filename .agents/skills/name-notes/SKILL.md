# 문서 작명

## 작명 기준

- 본문을 읽어 문서의 중심 주제를 파악한다. 검색할 핵심어를 앞에 두고, 주제만으로 부족할 때 목적이나 문서 종류를 덧붙인다.
- 제목만 보고 내용을 짐작할 수 있는 가장 짧은 표현을 고른다. 부수적인 설정, 세부 절차, 불필요한 `안내`·`참고`·`기록`을 나열하지 않는다.
- 같은 폴더의 유사 문서는 구분할 만큼만 구체화한다. 예: `Mattermost 배포`와 `Mattermost 도입 기록`.
- 지나치게 줄여 모호해지면 핵심어를 되살린다. 예: `Drive 전환 기록`보다 `Synology Drive 전환 기록`.
- 이미 짧고 명확하면 유지한다. 예: `SMTP Relay`, `CONNECT 배포 초안`. 일일 노트처럼 날짜가 식별자인 문서는 기존 날짜형 파일명을 유지한다.
- 파일명에는 경로 구분자나 운영체제에서 허용되지 않는 문자를 쓰지 않는다. 같은 폴더에 대소문자나 유니코드 표기만 다른 이름이 없는지도 확인한다.

## 절차

1. 본문과 같은 폴더의 유사 제목을 확인한다.
2. `현재 제목 → 제안 제목`과 짧은 근거를 제시한다. 유지할 제목도 필요에 따라 표시한다.
3. 제안이 기본이다. 파일명 변경을 요청받으면 대상 이름 충돌과 내부 링크를 확인하고, 폴더와 확장자를 유지한 채 이름을 변경한다. 변경으로 깨지는 위키링크·Markdown 링크·임베드 대상만 갱신하고 다시 확인한다.

폴더를 옮기거나 본문을 재작성하지 않는다.
