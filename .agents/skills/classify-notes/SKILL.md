# 문서 분류

## 판단 기준

- 파일명만 보지 말고 본문과 실제 사용 상태를 확인한다. 사용자가 알려 준 현행 업무 여부를 우선한다.
- Projects: 목표와 종료 조건이 있는 진행 중 작업. 완료되면 결과 기록을 Archives로 옮길 후보로 본다.
- Areas: 현재 업무에서 실제로 따르거나, 변경 시 갱신해야 하는 기준·절차·목록. 예: 실제로 적용하는 IP 할당 규칙, 현행 온보딩 체크리스트.
- Resources: 최신 상태로 유지할 책임은 없지만 다시 참고할 수 있는 지식·설정 예시·가이드. 사내 시스템을 다룬다는 이유만으로 Areas에 넣지 않는다.
- Archives: 완료·중단된 작업, 장애 보고서, 인수인계 시점의 구성 등 이력을 보존하는 문서. 과거 문서라도 현재 주된 용도가 재사용이면 Resources를 고려한다.
- 현행 절차와 과거 기록이 섞여 있으면 주된 용도로 분류하고, 필요하면 분리를 제안한다. 현행 여부가 불명확하면 근거와 함께 `확인 필요`로 표시한다.

## 절차

1. 기존 폴더 구조와 문서 범위를 확인한다. 폴더 이름이나 번호를 강제하지 않는다.
2. 각 문서의 `현재 경로 → 권장 폴더`와 판단 근거를 제시한다. 위치 유지도 명시한다.
3. 불필요한 하위 폴더를 만들지 않는다. 날짜별 일지처럼 묶어 탐색할 이유가 있는 경우는 예외로 둔다.
4. 제안이 기본이다. 적용을 요청받으면 대상 경로 충돌과 내부 링크를 확인한 뒤 이동하고, 문서 수와 링크·첨부 참조를 검증한다. 이동으로 깨지는 링크 대상만 필요한 범위에서 갱신한다.

파일명을 바꾸거나 본문을 다듬지 않는다. 첨부 삭제는 별도 요청이 있을 때만 수행한다.
