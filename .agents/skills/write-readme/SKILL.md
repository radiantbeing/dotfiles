# README 작성

## 작성 원칙

- 사용자의 구체적인 요구사항을 이 기본 규칙보다 우선한다.
- 저장소의 관련 파일을 확인하고, 확인되지 않은 명령어·경로·동작은 추측하지 않는다.
- 제목은 프로젝트 이름으로 간결하게 작성한다.
- 개요는 저장소의 주요 내용을 최대 3개의 불렛으로 요약한다.
- Markdown의 제목, 불렛, 코드 블록 등을 활용해 아웃라이너 구조로 작성한다.
- 불렛을 포함한 설명은 축약형이 아닌 완전한 문장으로 작성한다.
- 섹션명은 내용에 맞게 구체적으로 짓는다. 예를 들어 개발 서버 실행을 안내한다면 `시작하기`보다 `개발 서버 실행`을 사용한다.
- 저장소의 다른 파일에서 확인할 수 있는 기술 스택과 사양은 불필요하게 나열하지 않는다.
- 실행 명령어, 필요한 준비사항, 결과물 위치 등 독자에게 실용적인 정보는 요청과 맥락에 맞게 포함한다.
- 저장소에서 확인할 수 있는 사양이라도 사용자의 요청을 충족하거나 실행 절차를 이해하는 데 필요하면 포함한다.

## 검토

- 제목과 섹션이 내용을 정확하게 나타내는지 확인한다.
- 개요의 불렛이 3개 이하이고 설명이 완전한 문장인지 확인한다.
- 명령어와 경로가 실제 저장소 설정과 일치하는지 확인한다.
